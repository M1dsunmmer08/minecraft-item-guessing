# 记分与口径

## 1. 计分口径

| 动作 | 是否计问题数 | 是否计猜错 |
|---|---|---|
| 得到有效回答的普通是非问题 | 计 1 问 | 否 |
| 最终猜测（含猜中那次） | 计 1 问 | — |
| 最终猜测得到"否" | 计 1 问 | 累计 1 次猜错 |
| 普通属性问题得到"否" | 计 1 问 | 否 |
| 重复询问已确认问题 | 照常计数 | 否 |
| 有歧义被要求重写 | 不计 | 否 |
| 联网查询、读网页 | 不计 | 否 |
| 场外控制消息（暂停／重写／纠正／继续／口径裁定） | 不计 | 否 |
| 复盘分析、存档整理 | 不计 | 否 |

排名：**总有效问题数越少越好**；问题数相同时，猜错次数越少越好。
不限问题总数、不限猜错次数，不自行设 20 问上限，不提前宣布失败。

---

## 2. 属性确认 vs 最终猜测

- **属性确认**："它的本体是楼梯类吗？"得到"是"**不等于**猜中，只表示该描述成立。
- **最终猜测**必须原句使用：`我猜完整答案是"……"，对吗？` 只有出题人对完整答案回答"是"才算通关。
- 最终猜测可以组合多个已被确认的属性，这不违反"一问一条件"。
- 最终猜测得到"否"后继续提问，不要求出题人指出错在哪。

**提交闸门**：① 问过"是否存在必猜状态" ② 问过项数／类别 ③ 每项取值均已单独确认 —— 三项缺一不得提交。

---

## 3. 本 AI 持答案作答时的纪律

输出**只有**「是」或「否」。不解释、不提示、不补条件、不主动给线索、不评价问题好坏。

回答前四项自检：

1. 问的是"该物品**能够**具有"还是"答案**当前**具有"？——按出题时冻结的快照判定。
2. 是否在问**必猜项**？——只有写进答案的项才回答"是"，其余按"是否属于答案组成部分"如实回答。
3. 是否把"我不知道"当成了"否"？——未知不等于否定，不熟就联网核实。
4. 是否问的是"形状随相邻改变"和"水平延伸连接"混在一句里？——有歧义就判【重写：问题有歧义】。

场外消息处理：

| 消息 | 处理 |
|---|---|
| 【暂停】 | 停止推进，等待【继续】 |
| 【重写：问题有歧义】 | 保留题号，不计问题数，等对方改写 |
| 【纠正：第X问应为"是/否"】 | 替换该问回答并修正判断，不解释原因；已发生的计数不删除 |
| 【继续】 | 恢复答题 |
| 请求口径裁定 | 用一句是非问给出适用范围，裁定不计问题数 |

同一问题前后回答必须一致；确需纠正时明确说明"第X问应为"，不要静默改口。

---

## 4. 出题人自查（本 AI 出题时）

1. 开局前把答案写成**完整状态串**并冻结，中途不得更换或追加必猜条件。
2. 答案合法：基础物品可在该版本创造模式物品栏取出；状态为该版本真实支持。
3. 难度分级：无状态＝简单；1–2 项状态＝中等；3 项以上或含 `waterlogged`／`shape`／`half`＝困难。
4. 只回答"是／否"，不因为选手问得好而给提示，不因为问得差而催促。
5. 判定以开局快照为准，不以现实时间或游戏运行状态改变。

## 5. 复盘存档模板

通关或用户结束时，写入 `<工作区>/猜物品对局记录/`，文件名建议 `猜物品对局记录-<版本>-<答案简称>.md`：

```markdown
# 猜物品对局记录 · <答案简称>

谜底：<自然语言答案>
状态串：`minecraft:<id>[<state=value>,...]`

## 对局元信息
| 项目 | 内容 |
|---|---|
| 玩法 | 出题人固定完整答案，猜题人只问是非问题 |
| 版本口径 | Minecraft Java Edition <版本> 正式版原版 |
| 联网 | 可用 |
| 成绩 | 总问题数 N 问，猜错 M 次 |

## 完整问答
| 问号 | 问题（摘要） | 回答 |
|---|---|---|
| 1 | … | 是 |

## 答案核对
| 维度 | 取值 | 依据 |
|---|---|---|
| 本体 | … | … |

## 关键路径与失误
- 命中本体用时：第 N 问
- 失误/分水岭：…

## 速查
Q01 是 Q02 否 …
```

每次对局独立成档；已有归档目录时直接追加，不覆盖历史文件。
